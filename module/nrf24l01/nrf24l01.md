# NRF24L01+ MSPM0G3507 调用说明

本目录中的代码分为三层：

- `nrf24l01_freertos.c/.h`：FreeRTOS 业务任务推荐使用的线程安全封装。
- `nrf24l01_simple.c/.h`：推荐业务代码使用的便捷封装。
- `nrf24l01.c/.h`：芯片驱动，提供配置、发送、接收、寄存器访问和状态处理。
- `nrf24l01_port_mspm0.c/.h`：MSPM0G3507 硬件适配层。
- `nrf24l01_regs.h`：nRF24L01+ 命令、寄存器和位掩码。
- `test.c`、`nrf24l01_test.h`：MaixCAM ↔ MSPM0 双向通信测试。

FreeRTOS 任务用法详见 `nrf24l01_freertos.md`。

普通业务代码优先使用 `Nrf24Simple_*`。只有需要动态负载、修改射频参数或
寄存器诊断时，才直接使用 `Nrf24*` 底层接口。

## 1. 天猛星接线

| NRF24L01 | 天猛星 MSPM0G3507 |
| --- | --- |
| VCC | 3.3V |
| GND | GND |
| SCK | PB23 |
| MOSI | PB22 |
| MISO | PB21 |
| CE | PB24 |
| CSN | PB26 |
| IRQ | PB27 |

模块只能使用 3.3V 供电。建议在模块 VCC 与 GND 附近并联 100 nF 和
10–47 µF 电容。

## 2. 已验证默认配置

`Nrf24SimpleGetTianmengxingConfig()` 会填入当前工程已经通信验证通过的配置：

- GPIO 模拟 SPI：PB23/PB22/PB21
- CE/CSN/IRQ：PB24/PB26/PB27
- 地址：`D2 F0 F0 F0 A5`
- 频道：76
- 速率：1 Mbps
- 发射功率：-18 dBm
- CRC：2 字节
- 自动应答：开启
- 固定负载：32 字节
- 自动重发：15 次，间隔 1 ms

MaixCAM 与 MSPM0 两端的频道、地址、速率、CRC 和负载方式必须一致。

## 3. 最简初始化

```c
#include "nrf24l01_simple.h"

static Nrf24Simple_t g_radio;

static Nrf24Result_t RadioInit(void)
{
    Nrf24InitConfig_t config;

    Nrf24SimpleGetTianmengxingConfig(&config);
    return Nrf24SimpleInit(&g_radio, &config, true);
}
```

`Nrf24SimpleInit()` 的第三个参数为 `true` 时，初始化后立即进入接收模式；
为 `false` 时停留在待机模式。

初始化包含约 100 ms 的 nRF24L01 上电等待，属于阻塞调用。

## 4. 发送

```c
static const uint8_t message[] = "hello";
Nrf24Result_t result;

result = Nrf24SimpleSend(
    &g_radio,
    message,
    (uint8_t)(sizeof(message) - 1U),
    150U,
    true);

if (result == NRF24_RESULT_OK)
{
    /* 已收到接收端的硬件 ACK。 */
}
```

参数含义：

- `length`：应用数据长度，范围 1–32。
- `timeout_ms`：等待发送完成的超时。
- `resume_receive`：如果发送前处于接收模式，发送后是否恢复接收。

固定负载模式下，少于 32 字节的数据会自动在尾部补零。

`NRF24_RESULT_MAX_RETRIES` 表示自动重发耗尽，通常应检查对端供电、频道、
地址、距离和干扰；`NRF24_RESULT_TIMEOUT` 表示未在指定时间内得到最终状态。

硬件 ACK 只表示对端 NRF24L01 已收到数据，不表示对方业务代码已经处理。

## 5. 接收

非阻塞检查一包：

```c
uint8_t payload[NRF24_MAX_PAYLOAD_SIZE];
uint8_t length;
uint8_t pipe;
Nrf24Result_t result;

result = Nrf24SimpleReceive(
    &g_radio,
    payload,
    (uint8_t)sizeof(payload),
    &length,
    &pipe,
    0U);

if (result == NRF24_RESULT_OK)
{
    /* 处理 payload[0..length-1]。 */
}
else if (result == NRF24_RESULT_NO_DATA)
{
    /* 当前没有数据。 */
}
```

最多等待 500 ms：

```c
result = Nrf24SimpleReceive(
    &g_radio,
    payload,
    (uint8_t)sizeof(payload),
    &length,
    &pipe,
    500U);

if (result == NRF24_RESULT_TIMEOUT)
{
    /* 等待超时。 */
}
```

`Nrf24SimpleReceive()` 会自动进入接收模式。固定负载模式下返回长度为 32；
若协议只使用前几个字节，应在负载头中增加有效长度字段，不要依赖删除尾部零
来判断二进制数据长度。

## 6. 手动控制接收模式

```c
/* 保留 RX FIFO 中已有数据并进入接收模式。 */
Nrf24SimpleStartReceive(&g_radio, false);

/* 退出接收模式，进入已上电待机。 */
Nrf24SimpleStopReceive(&g_radio);

/* 丢弃旧数据后进入接收模式。 */
Nrf24SimpleStartReceive(&g_radio, true);
```

只有明确不需要旧包时才能将 `clear_pending` 设为 `true`。

## 7. 低功耗与底层访问

进入掉电模式：

```c
Nrf24SimplePowerDown(&g_radio);
```

需要读取寄存器或调用底层功能时：

```c
Nrf24_t *device = Nrf24SimpleGetDevice(&g_radio);
uint8_t status;

if (device != NULL)
    Nrf24GetStatus(device, &status);
```

## 8. 便捷 API 速查

| API | 作用 |
| --- | --- |
| `Nrf24SimpleGetTianmengxingConfig()` | 生成已验证的板级默认配置 |
| `Nrf24SimpleInit()` | 初始化，可选择立即监听 |
| `Nrf24SimpleIsInitialized()` | 判断是否初始化完成 |
| `Nrf24SimpleSend()` | 发送 1–32 字节并自动补齐固定负载 |
| `Nrf24SimpleStartReceive()` | 进入接收模式 |
| `Nrf24SimpleStopReceive()` | 退出接收模式 |
| `Nrf24SimpleReceive()` | 非阻塞或限时接收一包 |
| `Nrf24SimpleDataAvailable()` | 检查 RX FIFO 是否有数据 |
| `Nrf24SimplePowerDown()` | 进入低功耗模式 |
| `Nrf24SimpleGetDevice()` | 获取底层驱动实例 |

## 9. 自定义无线参数

先获取板级配置，再修改无线字段：

```c
Nrf24InitConfig_t config;
static const uint8_t address[5] = {
    0x11U, 0x22U, 0x33U, 0x44U, 0x55U
};

Nrf24SimpleGetTianmengxingConfig(&config);
config.channel = 80U;
config.output_power = NRF24_OUTPUT_POWER_NEG_6_DBM;
memcpy(config.tx_address, address, sizeof(address));
memcpy(config.rx_address_p0, address, sizeof(address));

Nrf24SimpleInit(&g_radio, &config, true);
```

使用 `memcpy()` 时需要包含 `<string.h>`。

## 10. 注意事项

- `Nrf24Simple*` 和底层驱动为阻塞式且未内置互斥锁；FreeRTOS 业务任务应
  使用 `Nrf24Rtos*` 接口。
- PB27 IRQ 当前用于电平查询，FreeRTOS 接收接口采用每 Tick 让出 CPU 的
  任务友好轮询方式。
- 接收后回复请求时，建议延时约 5 ms 再发送，给对端留出 PTX→PRX 切换时间。
- 共享 SPI 总线时，应用层必须保证一次完整驱动调用期间不会被其他设备打断。
- 若要改用硬件 SPI，将 `config.port.software_spi` 设为 `false`，并确认
  SysConfig 生成的 SPI 模式为 Mode 0、8 bit、MSB first。
